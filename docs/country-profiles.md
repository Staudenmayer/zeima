# Country profiles

Country-specific rules (legal limits, breaks, vacation, public holidays) are
data in `crates/time-core/jurisdictions/`. Adding or fixing a country needs no
Rust or Vue changes. See also [SPEC §5.13](SPEC.md).

> Profiles are best-effort defaults, not legal advice. Every profile lists the
> law texts it is based on in `sources`.

## Files

| File | Purpose |
|---|---|
| `<ID>.toml` | The profile. `<ID>` is the ISO 3166-1 alpha-2 code (`AT`, `DE`, …). |
| `<ID>.fixtures.toml` | Expected holidays and breaks; checked by `cargo test`. |
| `profile.schema.json` | JSON Schema of the profile format. Generated by `cargo test`; do not edit. Editors that understand `#:schema` comments (e.g. Even Better TOML) validate profiles while you type. |

## Add a country

1. Copy `AT.toml` to `<ID>.toml` and fill in every field:
   - `version`: `YYYY.N`. Bump it whenever a rule changes. Cached day results computed with an older version are recomputed.
   - `sources`: law names and links. Required.
   - `[work_time]`: limits in minutes. Leave out a limit the country does not have.
   - `[[breaks]]`: one entry per threshold. The rule with the highest `after_minutes` below the worked time applies. `min_part_minutes` is the shortest gap that counts towards the break.
   - `[vacation]`: statutory minimum for a full-time 5-day week.
   - `[[holidays]]`: public holidays of the whole country (see rules below). Use `day_off = false` for days worth showing that are not days off.
   - `[regions."<ID>-<code>"]`: ISO 3166-2 subdivisions with their extra holidays (`holidays = [...]`) or removed national ones (`remove_holidays = ["id"]`).
2. Register the file in `BUNDLED` in `crates/time-core/src/jurisdiction/mod.rs`, and its fixtures in `FIXTURES` in `jurisdiction/tests.rs`.
3. Write `<ID>.fixtures.toml` with dates taken from an official source, not from this program:
   - holidays for at least 3 years, including at least one region,
   - break requirements around each threshold (e.g. 360 → 0, 361 → 30).
4. Run `cargo test -p time-core --features db`. The tests check the fixtures, ISO codes, duplicate holidays and that every region resolves.
5. Open a pull request. Name the sources you used to check the fixtures.

## Holiday rules

| Rule | Example | Meaning |
|---|---|---|
| `fixed` | `{ fixed = "10-26" }` | Same date every year (`MM-DD`) |
| `easter_offset` | `{ easter_offset = 39 }` | Days after Western Easter Sunday (negative = before) |
| `orthodox_easter_offset` | `{ orthodox_easter_offset = 1 }` | Days after Orthodox Easter Sunday |
| `nth_weekday` | `{ nth_weekday = { month = 5, weekday = "mon", n = -1 } }` | n-th weekday of a month; `n = -1` is the last |
| `weekday_before` | `{ weekday_before = { month = 11, day = 23, weekday = "wed" } }` | Last such weekday strictly before the date |
| `weekday_after` | `{ weekday_after = { month = 6, day = 19, weekday = "fri" } }` | First such weekday strictly after the date |

Add `valid_from_year` / `valid_to_year` when a holiday was introduced or
abolished (e.g. Berlin's Women's Day from 2019).

## Known gaps

- **Switzerland**: only the federal days and the cantons of Zurich and Bern.
- **Germany**: holidays that apply only in parts of a state (Fronleichnam in parts of Saxony and Thuringia, Mariä Himmelfahrt in parts of Bavaria, Augsburger Friedensfest) are not included; users add them as company holidays.
- **Austria**: state patron days are not statutory holidays and are not included.
